# Plan 校验与幻觉观察

把 plan 输出判成"可用 / 不可用"这件事，比想象中脏。一方面模型会在召回不足的字段上用自身知识硬编，是幻觉重灾区；另一方面"一样的意思"在字段里有太多写法，字符串全匹配会把很多本来能过的样本打死。这篇记录这两块的当前结论和正在跑的校验 SOP。

## 幻觉观察：约 30% 的 plan 是模型"自己想的"

做了一轮人工抽样：对 label 和召回做 diff，约 30% 的 plan 输出里出现了召回给不到、只能由模型自身知识兜底的字段。典型场景是小众车型的配置项和版型——用户只提了个车系，模型就把"大概率配的功能"写进 where。

这块是后续 reward 要重点压制的方向。judge prompt 里需要把"召回未命中但字段被写进 plan"识别成可扣分项，而不是交给结构检验去打 fatal。

## 字段层面要做语义相似度

当前校验在大量自然语言字段上走"字符串全匹配"，对同义改写和格式差异非常脆弱（`通勤` vs `上下班通勤`、`加速快` vs `动力强加速迅猛`）。思路是**规则归一化优先，归一化失败再用 embedding 相似度兜底**——纯相似度一刀切容易把不同含义的字段混进来。

按字段盘一下进度。

已接入：

- 候选车系、车系版型（embedding + 覆盖匹配 + 尾缀兜底）
- 能源类型（`desc_similarity_threshold`）
- 车辆功能配置（`desc_similarity_threshold`）

还没做、但口径上已经明确该走相似度的：

- 二手车需求、车辆用途
- 车辆特点、配置倾向性（`价格低` vs `性价比高` 这类主观描述）
- 新能源配置：电池类型、电芯品牌、快充 / 慢充、800V 等自由文本
- 电机配置：电机类型、电机数、电机布局
- 用车人群：新手 / 年龄标签 / 家庭结构
- 内部配置、外部配置（同义改写密集）
- 其他需求、改装信息
- 车辆颜色（银灰 / 银色 / 珍珠白）
- 车辆类型、车身级别、驱动方式、变速箱配置、悬架配置、车门、座位布局（优先枚举映射，失败再相似度）

几个约定好的特殊规则，需要在校验里单独处理：

- `必要` 和 `强烈` 可以互换。
- 多出来的字段如果是"数量限制"，不判错。
- 座位布局只要总座位数一致就不算冗余条件（`2+2+2` 和 `6座` 等价）。
- 不同 field 但值相同不算冗余（`内部配置##方向盘加热` 和 `车辆功能配置##方向盘加热` 等价）。

## 当前校验 SOP

记录当前 plan 校验的实际判定逻辑，作为后续修改的基线。

### select

- output 包含 label 即可视为可用。
- output 比 label 少：output 的 select 数量 ≥ 5 时默认可用；否则按 label 做缺失检查并报错。

### where

除 `候选车系 / 车系版型` 外的 where 条件仍按原逻辑做 `字段 / 值 / 倾向性 / 排除` 全匹配。where 缺筛选条件算可用。

`候选车系 + 车系版型` 单独走 embedding 余弦相似度：抽取后拼成文本对比，相似度 ≥ `similarity_threshold` 视为相同。

多候选车系（≥ 2）场景下，把每个 `候选车系 + 紧随的车系版型` 看作一组，和 label 侧的组做一一覆盖匹配，只要有一组不过阈值就不可用。实现里会寻找一组能让所有 pair 都过阈值的匹配方式，避免仅因顺序差异误判。

为了鲁棒，车系相似度取下面四种对比的 max：

- output(车系+版型) vs label(车系+版型)
- output(车系) vs label(车系)
- output(车系+版型) vs label(车系)
- output(车系) vs label(车系+版型)

车系文本候选里额外加一份"去掉尾部英文字母后缀"的版本（`515CDI` → `515`），避免尾缀把相似度拉低。

Params block 对齐：`_block_key()` 只做字符串相等的情况下找不到对齐 key 时，用"候选车系 + 车系版型"的 max 相似度兜底，把 label block 对齐到最相近且过阈值的 output block。

`desc_similarity_threshold` 默认 0.7，当前用于车辆功能配置、能源类型。

版型替代字段绑定：只有 1 组候选车系的场景下，如果某侧缺车系版型但 where 里有座位布局，就把座位布局绑定为这组的版型，并从剩余 where 里消费掉。

### orderby

按 `字段 / 值 / 倾向性 / 排除` 做缺失 / 多余校验，顺序无关。当前只产出错误标签，不参与可用性判定。

### groupby

- 缺失：label 有但 output 没有。
- 多余：output 有但 label 没有。
- output 的 group_by 里出现"候选车系"直接报错。

同样只打标签，不参与可用性判定。
